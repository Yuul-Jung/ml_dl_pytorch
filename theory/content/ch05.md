## 이 장의 목표

1~4장에서 회귀, 이진분류, 다중분류를 선형 모델·MLP·CNN으로 풀었습니다. 이 장은 그 경험을 하나의 판단 절차로 정리합니다. 새 문제를 만났을 때 ⟪b⟫출력층 → 손실함수 → Optimizer → 학습 조건 → 검증 → 평가 지표⟪/b⟫를 어떤 순서와 근거로 고르는지가 주제입니다.

⟪box:쉽게 이해하기⟫

요리를 정할 때 "어떤 냄비를 쓸까"보다 "무엇을 만들까"를 먼저 정하듯, 학습 설정은 "어떤 모델을 쓸까"보다 "정답이 어떻게 생겼나"를 먼저 봅니다. 정답 모양이 정해지면 출력층과 손실함수는 거의 자동으로 따라옵니다.

⟪/box⟫

⟪box:꼭 기억할 점⟫

- 판단 기준은 "어떤 모델인가?"가 아니라 "정답 y가 어떻게 생겼는가?"입니다.
- 모델 마지막은 로짓으로 끝내고, Sigmoid·Softmax는 손실함수(`BCEWithLogitsLoss`, `CrossEntropyLoss`) 안에서 계산합니다.
- Loss는 학습용, Metric은 평가용입니다. 불균형 데이터에서 Accuracy만 보면 위험합니다.

⟪/box⟫

## 핵심 원칙: 모델보다 Target이 먼저

![슬라이드 1 · 학습 설정 선택 기준](img/ch05_slide01.jpg)

![슬라이드 2 · MLP냐 CNN이냐보다 먼저 확인할 것](img/ch05_slide02.jpg)

MNIST를 3장의 MLP로 풀든 4장의 CNN으로 풀든, 정답이 0~9 클래스 번호이므로 ⟪b⟫둘 다 다중분류⟪/b⟫입니다. 출력은 10개 로짓, 손실은 `CrossEntropyLoss`로 같습니다. 모델 구조는 입력 특징을 처리하는 방식일 뿐이고, 손실은 Target과 출력의 관계로 정해집니다.

## 전체 의사결정 파이프라인

![슬라이드 3 · 앞 단계가 뒤 단계를 결정한다](img/ch05_slide03.jpg)

```flow
문제 정의
Target 형태 (실수? 0/1? 클래스 번호? 여러 0/1?)
출력층 (노드 수와 의미)
Loss
```

앞 단계가 뒤 단계를 결정합니다. Target이 실수면 회귀 → MSE/L1, 0/1이면 이진분류 → BCEWithLogitsLoss, 클래스 번호면 다중분류 → CrossEntropyLoss입니다.

## 문제 유형은 Target 모양으로 구분한다

![슬라이드 4 · Target 형태별 문제 유형과 손실](img/ch05_slide04.jpg)

| Target 형태 | 문제 유형 | 출력층 | Loss |
|---|---|---|---|
| 실수 `[N, 1]` float | Regression(회귀) | 노드 1개, 활성화 없음 | `MSELoss` / `L1Loss` |
| 0/1 `[N, 1]` float | Binary(이진분류) | 로짓 1개 | `BCEWithLogitsLoss` |
| 클래스 번호 `[N]` long | Multi-class(다중분류) | 로짓 C개 | `CrossEntropyLoss` |
| 여러 0/1 `[N, C]` float | Multi-label(다중레이블) | 로짓 C개 | `BCEWithLogitsLoss` |

## ① 회귀: 실수값을 예측한다

![슬라이드 5 · 회귀의 흐름과 평가 지표](img/ch05_slide05.jpg)

면적과 방 개수로 집값을 예측하는 것처럼, 정답이 연속 실수면 회귀입니다(1장). 출력층은 노드 1개이며 값의 범위를 제한하지 않도록 활성화 함수를 두지 않습니다.

- `MSELoss` — 오차 제곱 평균. 큰 오차에 민감합니다.
- `L1Loss` — 오차 절댓값 평균(MAE와 같은 식). 이상치에 덜 민감합니다.
- 평가 지표: MAE, RMSE(작을수록 좋음), `$R^2$`(1에 가까울수록 좋고, 평균으로만 예측하는 것보다 못하면 음수도 나옴)

## ② 이진분류: 두 가지 중 하나

![슬라이드 6 · 로짓 1개와 BCEWithLogitsLoss](img/ch05_slide06.jpg)

학습할 때는 모델에 Sigmoid를 넣지 않고 로짓 1개를 `BCEWithLogitsLoss`에 넣습니다. Target은 `[N, 1]` float이며 값은 0.0 또는 1.0입니다. 추론할 때만 로짓 → Sigmoid → 확률 → 0.5 기준으로 0/1을 정합니다(2장). 0.5는 기본값일 뿐이며, 놓치면 안 되는 문제(질병 진단)라면 기준을 낮춰 Recall을 높이기도 합니다.

## ③ 다중분류: 여러 클래스 중 하나

![슬라이드 7 · 로짓 C개와 CrossEntropyLoss](img/ch05_slide07.jpg)

MNIST처럼 정답이 여러 클래스 중 정확히 하나면 다중분류입니다(2·3·4장). 출력은 `[N, C]` 로짓, Target은 원-핫이 아닌 클래스 번호 `[N]` long입니다. 배치 4개면 출력 `[4, 10]`, 정답 `tensor([7, 2, 1, 9])`입니다.

참고로 최근 PyTorch의 `CrossEntropyLoss`는 `[N, C]` float 확률 분포도 정답으로 받을 수 있습니다(Label Smoothing이나 지식 증류에 쓰임). 일반적인 다중분류에서는 클래스 번호를 씁니다.

## ④ 다중레이블: 여러 정답이 동시에 가능

![슬라이드 8 · 클래스별 독립 Sigmoid](img/ch05_slide08.jpg)

사진 한 장에 사람·자동차·신호등이 함께 있을 수 있듯, 정답이 하나로 정해지지 않으면 다중레이블입니다. Target은 `[N, C]` float이고 각 값이 0/1입니다. 클래스끼리 경쟁하지 않으므로 Softmax가 아니라 ⟪b⟫클래스마다 독립적인 Sigmoid⟪/b⟫를 쓰며, 손실은 이진분류와 같은 `BCEWithLogitsLoss`를 C개 클래스에 동시에 적용합니다.

## Loss Function 선택 요약

![슬라이드 9 · 손실함수 지도와 주의할 조합](img/ch05_slide09.jpg)

| 조합 | 모델 출력 | 주의 |
|---|---|---|
| `BCELoss` | Sigmoid를 거친 확률 | 확률이 0·1로 반올림되면 `log 0` 문제. 가능하면 아래 것을 사용 |
| `BCEWithLogitsLoss` | 로짓 | Sigmoid 포함. 수치적으로 안정 |
| `CrossEntropyLoss` | 로짓 | Log-Softmax 포함. 모델에 Softmax를 또 넣지 않음 |
| Loss ≠ Metric | — | Loss는 미분 가능한 학습 기준, Metric은 사람이 읽는 평가 기준 |

실무 기본은 "모델 마지막은 로짓을 그대로 내보내고, Loss 내부의 Sigmoid/Softmax 계산을 활용한다"입니다.

## Optimizer는 수정 방법을 결정한다

![슬라이드 10 · SGD부터 AdamW까지](img/ch05_slide10.jpg)

Loss는 "얼마나 틀렸는가"를, Optimizer는 "W와 b를 어떻게 고칠 것인가"를 담당합니다.

| Optimizer | 갱신 방식 | 쓰임 |
|---|---|---|
| SGD | `$W\mathrel{:=} W-\alpha\nabla L$` (1장의 식 그대로) | 원리 학습 |
| SGD + Momentum | 이전 이동 방향을 관성처럼 누적해 함께 이동 | 진동을 줄여 안정화 |
| Adam | 파라미터마다 기울기의 평균과 크기를 따로 추적해 보폭 자동 조절 | 빠른 초기 실험 |
| AdamW | Adam에서 Weight Decay(가중치 감쇠)를 기울기와 분리해 적용 | 대규모 모델, Transformer 계열 |

## 학습률 · 배치 크기 · 에폭

![슬라이드 11 · 세 하이퍼파라미터의 영향](img/ch05_slide11.jpg)

| 설정 | 너무 크면 | 너무 작으면 |
|---|---|---|
| Learning Rate | 진동·발산 (1장의 `lr=0.25` 예) | 학습이 매우 느림 |
| Batch Size | 기울기가 안정적이지만 메모리 사용 증가, 갱신 횟수 감소 | 기울기 변동이 커짐 |
| Epoch | Overfitting 가능(Validation Loss 상승) | 덜 배운 상태(Underfitting) |

이런 값은 학습 전에 사람이 정하는 Hyperparameter(하이퍼파라미터)이며, 반드시 Loss 그래프와 Validation 결과를 함께 보면서 조정합니다.

## 데이터 전처리: Train 기준만 사용한다

![슬라이드 12 · 정상 과정과 데이터 누수](img/ch05_slide12.jpg)

표준화(평균을 빼고 표준편차로 나누기) 같은 전처리 통계는 **Train 데이터에서만** 계산하고, 그 값으로 Train·Validation·Test를 똑같이 변환합니다. Test에서 평균과 표준편차를 따로 계산하면 Test 정보가 전처리에 새어 들어가는 Data Leakage(데이터 누수)가 생기고, 성능이 실제보다 좋게 보입니다. Test는 마지막까지 "처음 보는 데이터"처럼 유지합니다.

## 데이터 분리와 학습 상태 진단

![슬라이드 13 · Train / Validation / Test 분리와 진단](img/ch05_slide13.jpg)

예를 들어 전체를 Train 80% · Test 20%로 나누고, 다시 Train 80% 안에서 20%를 Validation으로 떼면 최종 비율은 Train 64% · Validation 16% · Test 20%입니다.

| 상태 | Train Loss | Validation Loss | 대응 |
|---|---|---|---|
| 정상 학습 | ↓ | ↓ | 계속 학습 |
| Underfitting | 높음 | 높음 | 모델 키우기, 더 오래 학습, 학습률 점검 |
| Overfitting | ↓ | ↑ | Validation 최저점에서 멈추기(Early Stopping), Dropout·데이터 증강·Weight Decay |

## MLP와 CNN은 앞부분만 다르다

![슬라이드 14 · 입력 처리 방식은 다르고 출력층과 Loss는 같다](img/ch05_slide14.jpg)

MLP(28×28 → Flatten → Linear/ReLU)와 CNN(28×28 → Conv/ReLU/Pooling)은 입력을 처리하는 앞부분이 다를 뿐, 같은 다중분류 문제라면 "10개 중 하나 선택 → 10 Logits → CrossEntropyLoss"라는 끝부분은 같습니다. 모델을 바꿔도 손실과 평가 코드는 그대로 둘 수 있다는 뜻입니다.

## Metric은 문제 유형에 맞춰 해석한다

![슬라이드 15 · 문제 유형별 평가 지표](img/ch05_slide15.jpg)

| 문제 유형 | 대표 Metric |
|---|---|
| 회귀 | MAE, RMSE, `$R^2$` |
| 이진분류 | Accuracy, Precision, Recall, F1 |
| 다중분류 | Accuracy, Macro F1 |
| 다중레이블 | Micro F1, Macro F1 |

```math
\text{Precision}=\frac{TP}{TP+FP},\qquad\text{Recall}=\frac{TP}{TP+FN},\qquad F_1=\frac{2\cdot\text{Precision}\cdot\text{Recall}}{\text{Precision}+\text{Recall}}
```

`$TP$`는 양성을 양성으로 맞힌 수, `$FP$`는 음성을 양성으로 잘못 예측한 수, `$FN$`은 양성을 놓친 수입니다. Precision은 "양성이라고 한 것 중 진짜 비율", Recall은 "진짜 양성 중 찾아낸 비율"입니다. Macro F1은 클래스별 F1을 단순 평균해 작은 클래스도 똑같이 반영하고, Micro F1은 전체 `$TP, FP, FN$`을 합쳐 한 번에 계산합니다.

## 코드로 확인하기

코드 박스: theory/code/ch05_training_setup.py 핵심 발췌 · 실행 통과(Python 3.13, NumPy 2.5)

```python
import numpy as np


def choose(y):
    # 정답 y의 자료형과 모양만 보고 문제 유형과 손실함수를 고른다
    y = np.asarray(y)
    if np.issubdtype(y.dtype, np.integer) and y.ndim == 1:
        return "다중분류 → 출력 C개 Logit, CrossEntropyLoss"
    if y.ndim == 2 and set(np.unique(y)) <= {0.0, 1.0}:
        if y.shape[1] == 1:
            return "이진분류 → 출력 1개 Logit, BCEWithLogitsLoss"
        return "다중레이블 → 출력 C개 Logit, BCEWithLogitsLoss"
    return "회귀 → 출력 1개 실수, MSELoss 또는 L1Loss"


print(choose(np.array([[3.5], [2.1]])))            # 집값
print(choose(np.array([[1.0], [0.0]])))            # 합격 여부
print(choose(np.array([7, 2, 1])))                 # 숫자 클래스
print(choose(np.array([[1.0, 1.0, 0.0, 1.0]])))    # 여러 태그

# 불균형 데이터: 양성 5%인데 전부 0이라고 예측하면
y = np.zeros(1000, dtype=int)
y[:50] = 1
pred = np.zeros(1000, dtype=int)
tp = int(((pred == 1) & (y == 1)).sum())
fn = int(((pred == 0) & (y == 1)).sum())
print(f"Accuracy {(pred == y).mean():.3f}  Recall {tp / (tp + fn):.3f}")
```

실행 결과: 이번 정리에서 직접 실행

```text
회귀 → 출력 1개 실수, MSELoss 또는 L1Loss
이진분류 → 출력 1개 Logit, BCEWithLogitsLoss
다중분류 → 출력 C개 Logit, CrossEntropyLoss
다중레이블 → 출력 C개 Logit, BCEWithLogitsLoss
Accuracy 0.950  Recall 0.000
```

⟪box:코드 풀이⟫

- `choose(y)` — 이 장의 표를 코드로 옮긴 것입니다. 정수 1차원이면 다중분류, 0/1 2차원이면 열 수로 이진분류와 다중레이블을 나누고, 나머지는 회귀로 봅니다. 교육용 판별 규칙이므로 실제 문제에서는 Target의 의미를 먼저 확인합니다.
- 불균형 예시 — 양성이 5%뿐이면 무조건 0이라고만 해도 Accuracy가 95%입니다. 그런데 Recall은 0으로, 양성을 하나도 찾지 못했습니다. Accuracy만 보면 이런 쓸모없는 모델을 좋은 모델로 착각합니다.
- 표준화 예시 — 파일 전체를 실행하면 4번에서 확인할 수 있습니다. Test 분포가 Train과 다를 때, Train 통계로 변환하면 그 차이(평균 +0.89)가 드러나지만 Test 통계로 변환하면 평균이 0으로 지워집니다. 실제 서비스에서는 미래 데이터의 통계를 미리 알 수 없으므로, Train 통계만 쓰는 쪽이 정직한 평가입니다.

⟪/box⟫

## PyTorch로 옮기기

코드 박스: PyTorch 예시 · Python · 미검증(이 환경에 PyTorch 미설치)

```python
import torch
import torch.nn as nn

N, D, C = 4, 8, 3
x = torch.randn(N, D)

# 문제 유형별 (출력층, 손실, 정답) 조합
setups = {
    "회귀": (nn.Linear(D, 1), nn.MSELoss(), torch.randn(N, 1)),
    "이진분류": (nn.Linear(D, 1), nn.BCEWithLogitsLoss(), torch.randint(0, 2, (N, 1)).float()),
    "다중분류": (nn.Linear(D, C), nn.CrossEntropyLoss(), torch.randint(0, C, (N,))),
    "다중레이블": (nn.Linear(D, C), nn.BCEWithLogitsLoss(), torch.randint(0, 2, (N, C)).float()),
}
for name, (head, loss_fn, target) in setups.items():
    out = head(x)
    print(f"{name:<6} 출력 {list(out.shape)}  정답 {list(target.shape)} {target.dtype}  손실 {loss_fn(out, target).item():.3f}")

# 전처리: Train 통계로 모든 데이터를 변환
train_x, test_x = torch.randn(800, D), torch.randn(200, D)
mean, std = train_x.mean(dim=0), train_x.std(dim=0)
train_x, test_x = (train_x - mean) / std, (test_x - mean) / std

# Optimizer: 원리 SGD, 안정화 Momentum, 빠른 실험 Adam, 대규모 AdamW
model = nn.Linear(D, C)
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.01)
```

⟪box:코드 풀이⟫

- `setups` — 표의 네 가지 조합을 그대로 만든 것입니다. 출력 노드 수, 정답 모양, 정답 자료형(`float`/`long`)이 서로 짝이 맞아야 손실이 계산됩니다. 예를 들어 다중분류 정답을 `float`으로 주거나 이진분류 정답을 `long`으로 주면 자료형 오류가 납니다.
- `torch.randint(0, 2, (N, 1)).float()` — 0/1 정수를 만든 뒤 `BCEWithLogitsLoss`가 요구하는 실수형으로 바꿉니다.
- `mean, std = train_x.mean(dim=0), train_x.std(dim=0)` — 특성(열)마다 Train에서만 통계를 계산하고, 같은 값으로 Test를 변환합니다.
- `AdamW(..., weight_decay=0.01)` — 가중치를 매 단계 조금씩 0 쪽으로 당겨 과적합을 줄입니다.

⟪/box⟫

## 스스로 점검

1. 내일 기온(실수)을 예측하는 문제의 출력층과 손실은? → 노드 1개(활성화 없음), `MSELoss` 또는 `L1Loss`입니다.
2. 영화 장르(액션·코미디·로맨스, 여러 개 가능)를 맞히는 문제의 정답 모양은? → `[N, 3]` float(0/1)이고 손실은 `BCEWithLogitsLoss`입니다.
3. Train Loss와 Validation Loss가 모두 높게 멈춰 있습니다. 무슨 상태인가요? → Underfitting입니다. 모델 용량, 학습 시간, 학습률을 점검합니다.
4. 사기 거래가 0.1%인 데이터에서 Accuracy 99.9%는 좋은 결과인가요? → 알 수 없습니다. 전부 정상이라고 해도 99.9%이므로 Recall·Precision·F1을 봐야 합니다.
