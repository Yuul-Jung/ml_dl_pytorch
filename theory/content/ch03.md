## 이 장의 목표

2장의 분류기는 입력과 출력 사이에 층이 하나뿐인 ⟪b⟫선형 모델⟪/b⟫이었습니다. 이 장은 그 사이에 Hidden Layer(히든 레이어, 은닉층)를 넣어 MLP(Multi-Layer Perceptron, 다층 퍼셉트론)를 만들고, 손글씨 숫자 MNIST로 실제 딥러닝 학습 절차 전체를 정리합니다.

1. 선형 층 사이에 ⟪b⟫활성화 함수⟪/b⟫를 넣어야 층을 쌓는 의미가 생기는 이유
2. 데이터를 Train·Validation·Test로 나누고, **배치** 단위로 학습하는 구조
3. 순전파 → 손실 → 역전파 → 갱신을 반복하는 ⟪b⟫학습 루프⟪/b⟫와 평가 방법

⟪box:쉽게 이해하기⟫

선형 모델은 직선(평면) 하나로만 세상을 나눕니다. 은닉층은 입력을 여러 방향에서 본 "중간 특징"을 만들고, 활성화 함수는 그 특징을 구부려 줍니다. 구부릴 수 있는 층을 여러 번 쌓으면 아주 복잡한 경계도 표현할 수 있습니다. 이것이 딥러닝의 "깊이"입니다.

⟪/box⟫

⟪box:꼭 기억할 점⟫

- `Linear` 사이에 `ReLU` 같은 비선형 활성화가 없으면 몇 층을 쌓아도 선형 모델 하나와 같습니다.
- 모델 마지막은 ⟪b⟫로짓⟪/b⟫으로 끝내고, Softmax는 `CrossEntropyLoss`에 맡깁니다.
- Validation은 학습 중 모델 선택에, Test는 학습이 끝난 뒤 **딱 한 번** 최종 확인에만 씁니다.

⟪/box⟫

## 인공지능·머신러닝·딥러닝

![슬라이드 2 · 인공지능 ⊃ 머신러닝 ⊃ 딥러닝](img/ch03_slide02.jpg)

인공지능은 사람의 지적 능력을 컴퓨터로 구현하는 기술 전체이고, 그 안에서 데이터로부터 스스로 규칙을 배우는 방법이 머신러닝, 다시 그 안에서 깊은 인공신경망을 쓰는 방법이 딥러닝입니다. 1·2장의 선형회귀·로지스틱 회귀는 머신러닝, 이 장의 MLP와 4장의 CNN은 딥러닝에 속합니다.

![슬라이드 3 · 머신러닝과 딥러닝의 구조 차이](img/ch03_slide03.jpg)

두 구조의 학습 고리(입력 → 예측 → 손실 → Optimizer 갱신)는 똑같습니다. 차이는 입력층과 출력층 사이에 ⟪b⟫은닉층이 있느냐⟪/b⟫뿐입니다. 데이터가 층을 차례로 지나 예측을 만드는 과정을 Feed Forward(피드 포워드, 순전파)라고 합니다.

## 다층 퍼셉트론

![슬라이드 4 · MLP 구조와 뉴런 하나의 계산](img/ch03_slide04.jpg)

뉴런(노드) 하나는 2장의 로지스틱 회귀와 같은 일을 합니다. 입력에 가중치를 곱해 더하고 편향을 더한 뒤, 활성화 함수 `$f$`를 통과시킵니다.

```math
a=f\!\left(\sum_i w_ix_i+b\right)
```

층 하나는 이런 뉴런을 여러 개 나란히 둔 것이고, 행렬로 쓰면 `$a=f(XW+b)$`입니다. MLP는 이 층을 여러 번 쌓습니다.

```math
h=f(XW_1+b_1),\qquad z=hW_2+b_2
```

⟪box:고급 해설 · 활성화 함수가 꼭 필요한 이유⟫

활성화 함수를 빼면 두 층은 `$(XW_1+b_1)W_2+b_2=X(W_1W_2)+(b_1W_2+b_2)$`가 되어, 가중치 `$W_1W_2$` 하나짜리 선형 층과 똑같아집니다. 층을 아무리 쌓아도 표현력이 늘지 않습니다. 슬라이드 4의 `nn.Linear(1, 8), nn.Linear(8, 1), nn.Sigmoid()`가 바로 이 경우라서, 은닉층 8개를 넣었지만 결과는 처음의 `nn.Linear(1, 1), nn.Sigmoid()`와 같은 로지스틱 회귀입니다. 두 `Linear` 사이에 `nn.ReLU()`를 넣어야 MLP가 됩니다. 아래 코드 6번 결과가 이 사실을 수치로 보여 줍니다.

⟪/box⟫

## 딥러닝 MLP의 구성 요소

![슬라이드 5 · 입력층부터 손실함수까지의 구성](img/ch03_slide05.jpg)

| 구성 요소 | 역할 |
|---|---|
| 입력층 | 28×28 이미지를 `flatten`해 784개짜리 1차원 벡터로 입력 |
| 은닉층 | 1개 이상의 완전연결(Fully Connected) 층. 각 노드가 앞 층의 모든 노드와 연결 |
| ReLU | `$\mathrm{ReLU}(x)=\max(0,x)$`. 양수는 그대로, 음수는 0 |
| Dropout | 학습 중 일부 노드를 확률적으로 꺼서 과적합을 줄이는 정규화 기법(선택) |
| 출력층 | 클래스 수만큼의 노드. 각 노드는 해당 클래스의 점수(로짓)를 출력 |
| Softmax | 점수를 합이 1인 확률로 변환 |

ReLU(Rectified Linear Unit)는 계산이 단순하고, 양수 구간의 기울기가 항상 1이어서 층이 깊어져도 기울기가 잘 전달됩니다. 시그모이드는 입력이 크거나 작으면 기울기가 0에 가까워져 깊은 신경망에서 학습이 멈추기 쉽습니다(기울기 소실).

![슬라이드 6 · PyTorch 구현에서는 출력층이 로짓으로 끝난다](img/ch03_slide06.jpg)

슬라이드 5는 개념을 설명하려고 Softmax를 층으로 그렸지만, PyTorch 구현(슬라이드 6)에서는 모델이 **로짓에서 끝나고**, Softmax는 `CrossEntropyLoss` 안에서 계산됩니다. 학습 후 화살표는 역전파 → Optimizer → `W, b` 갱신으로 돌아갑니다.

## Train·Validation·Test 분리

![슬라이드 9 · 학습 데이터에서 검증 데이터를 떼어 낸다](img/ch03_slide09.jpg)

![슬라이드 10 · 세 데이터의 역할](img/ch03_slide10.jpg)

| 데이터 | 언제 | 무엇에 |
|---|---|---|
| Train | 학습 중 | 손실을 계산해 `W, b`를 갱신 |
| Validation | 학습 중, 매 에폭 | 과적합 확인, 학습률·구조·에폭 같은 설정 선택 |
| Test | 학습이 모두 끝난 뒤 | 처음 보는 데이터에서의 최종 성능 확인 |

슬라이드 9의 85% : 15%는 나누는 개념을 보여 주는 예시 비율입니다. 실습 코드는 학습 데이터 60,000장을 `random_split`으로 ⟪b⟫55,000장(약 91.7%)과 5,000장(약 8.3%)⟪/b⟫으로 나눕니다. 비율은 데이터 양에 따라 정하며, 중요한 원칙은 Test를 학습 과정에서 완전히 떼어 두는 것입니다.

## 배치와 DataLoader

![슬라이드 11 · 전체를 한 번에 넣지 않고 배치로 나눈다](img/ch03_slide11.jpg)

1·2장처럼 전체 데이터를 한 번에 넣으면 데이터가 클 때 시간이 오래 걸리고 메모리가 부족합니다. 그래서 32개, 64개처럼 **Batch(배치)** 단위로 잘라 차례로 학습합니다. 배치 하나로 계산한 기울기는 전체 기울기의 근사이지만, 훨씬 자주 갱신할 수 있어 전체적으로 더 빨리 배웁니다. 이 방식을 Mini-batch SGD(미니배치 확률적 경사하강법)라고 합니다.

![슬라이드 12 · Dataset과 DataLoader의 역할](img/ch03_slide12.jpg)

- `Dataset` — 입력과 정답을 저장하고 `i`번째 샘플을 꺼내 줍니다.
- `DataLoader` — `Dataset`을 배치 크기만큼 묶어 차례로 건네줍니다.

![슬라이드 13 · 배치 하나의 Shape](img/ch03_slide13.jpg)

`batch_size=64`이면 배치 이미지는 `[64, 1, 28, 28]`, 배치 정답은 `[64]`입니다. 학습용은 `shuffle=True`로 매 에폭 순서를 섞어 모델이 순서를 외우지 못하게 하고, 검증·테스트용은 `shuffle=False`로 결과를 재현 가능하게 둡니다.

## Batch · Iteration · Epoch

![슬라이드 14 · 세 용어의 관계](img/ch03_slide14.jpg)

| 용어 | 뜻 | MNIST 예 |
|---|---|---|
| Batch Size | 한 번의 갱신에 쓰는 샘플 수 | 64장 |
| Iteration | 배치 1개로 `W, b`를 한 번 갱신 | 64장 학습 → 1회 갱신 |
| Epoch | 학습 데이터 전체를 한 번 다 봄 | 55,000장 = 860 Iteration |

```math
\text{Iteration/Epoch}=\left\lceil\frac{55{,}000}{64}\right\rceil=860,\qquad 860\times5=4{,}300
```

`$55{,}000=64\times859+24$`이므로 마지막 배치는 24장입니다. `DataLoader(..., drop_last=True)`로 두면 이 배치를 버리고 에폭당 859번 갱신합니다.

## 모델 구조와 파라미터 수

![슬라이드 15 · 28×28을 784개로 펼치는 MLP](img/ch03_slide15.jpg)

```flow
입력 `[N, 1, 28, 28]`
`Flatten` → `[N, 784]`
`Linear(784, 128)` → `ReLU` → `Dropout(0.2)` → `[N, 128]`
`Linear(128, 10)` → 로짓 `[N, 10]`
```

| 층 | 가중치 | 편향 | 합계 |
|---|---|---|---|
| `Linear(784, 128)` | `$784\times128=100{,}352$` | 128 | 100,480 |
| `Linear(128, 10)` | `$128\times10=1{,}280$` | 10 | 1,290 |
| 전체 | | | **101,770** |

`Flatten`, `ReLU`, `Dropout`에는 학습할 파라미터가 없습니다. 반복(Iteration)마다 이 101,770개가 모두 함께 갱신되며, 학습 중 개수는 변하지 않습니다.

## 출력, 정답, CrossEntropyLoss

![슬라이드 16 · 로짓과 정답 클래스 번호](img/ch03_slide16.jpg)

모델 출력은 `[N, 10]` 로짓이고, 정답은 `[N]` 모양의 클래스 번호(`torch.long`)입니다. 예를 들어 배치 크기 4이면 `logits.shape`는 `[4, 10]`, `target`은 `tensor([7, 2, 1, 9])`입니다. `CrossEntropyLoss`가 로짓에 로그-소프트맥스를 적용하고 정답 위치의 값을 꺼내 2장의 크로스엔트로피를 계산합니다. 확률이 필요하면 추론할 때만 `torch.softmax(logits, dim=1)`을 씁니다.

## 학습 루프와 역전파

![슬라이드 17 · 한 번의 갱신 순서](img/ch03_slide17.jpg)

```flow
기울기 초기화 `optimizer.zero_grad()`
순전파 `logits = model(images)`
손실 계산 `loss = loss_function(logits, labels)`
역전파 `loss.backward()`
가중치 갱신 `optimizer.step()`
```

Backpropagation(백프로퍼게이션, 역전파)은 손실에서 출발해 출력층 → 은닉층 → 입력층 방향으로 ⟪b⟫연쇄법칙⟪/b⟫을 적용해 모든 가중치의 기울기를 한 번에 구하는 방법입니다.

```math
\frac{\partial L}{\partial W_1}=\frac{\partial L}{\partial z}\cdot\frac{\partial z}{\partial h}\cdot\frac{\partial h}{\partial W_1}
```

각 층은 "뒤에서 넘어온 기울기 × 자기 자신의 국소 기울기"만 계산해 앞 층으로 넘깁니다. 2장에서 본 `$\partial L/\partial z=S-L$`이 출발점이고, ReLU는 양수였던 자리만 기울기를 통과시킵니다. PyTorch의 Autograd(자동 미분)가 이 계산을 `loss.backward()` 한 줄로 처리합니다.

## 평가: Validation과 Test

![슬라이드 18 · 평가 함수의 절차](img/ch03_slide18.jpg)

```flow
`model.eval()` — Dropout을 끄는 평가 모드
`torch.no_grad()` — 기울기 계산을 멈춰 메모리·시간 절약
배치별 손실을 누적해 평균 Loss 계산
`argmax`로 맞힌 개수를 세어 Accuracy 계산
```

Validation과 Test는 같은 평가 함수를 쓰지만 목적이 다릅니다. Test 결과를 보고 학습률이나 구조를 다시 고르면, Test가 사실상 Validation이 되어 최종 성능을 부풀리게 됩니다.

⟪box:고급 해설 · Dropout과 학습/평가 모드⟫

`nn.Dropout(p=0.2)`는 학습 모드에서 각 값을 20% 확률로 0으로 만들고, 남은 값은 `$\frac{1}{1-p}=1.25$`배로 키웁니다(Inverted Dropout). 그래서 평균적인 출력 크기가 평가 모드와 같게 유지됩니다. 평가 모드(`model.eval()`)에서는 아무것도 끄지 않고 그대로 통과시킵니다. `model.eval()`을 빼먹으면 예측할 때마다 결과가 달라지는 이유가 여기에 있습니다. 학습을 다시 시작할 때는 `model.train()`으로 돌려놓습니다.

⟪/box⟫

## 학습 곡선 읽기

![슬라이드 19 · Train Loss와 Validation Loss](img/ch03_slide19.jpg)

5 에폭 동안 Train Loss는 0.3803 → 0.0921, Validation Loss는 0.2058 → 0.0988로 함께 줄었습니다. 두 손실이 함께 감소하면 정상적인 학습입니다. Train Loss는 계속 줄어드는데 Validation Loss가 다시 오르기 시작하면 Overfitting(과적합)을 의심합니다.

1 에폭에서 Train Loss(0.38)가 Validation Loss(0.21)보다 큰 것은 오류가 아닙니다. Train Loss는 에폭 **도중⟪b⟫ 계속 좋아지는 모델의 손실을 평균한 값이라 초반의 큰 손실이 섞여 있고, 학습 중에는 Dropout이 켜져 있어 일부러 불리한 조건에서 잰 값이기 때문입니다. Validation Loss는 에폭이 ⟪/b⟫끝난** 모델을 Dropout 없이 잽니다.

![슬라이드 20 · Train Accuracy와 Validation Accuracy](img/ch03_slide20.jpg)

정확도는 Train 0.8944 → 0.9717, Validation 0.9388 → 0.9706입니다. Train 정확도만 보지 말고, Validation 정확도가 함께 오르는지와 둘의 차이가 벌어지지 않는지를 확인합니다.

## MLP의 한계와 CNN

![슬라이드 23 · MLP의 한계와 다음 확장](img/ch03_slide23.jpg)

MLP는 이미지를 784개짜리 긴 벡터로 펼치므로, 바로 옆에 붙어 있던 픽셀이 무엇인지라는 ⟪b⟫위치 관계⟪/b⟫를 잃습니다. 같은 숫자가 몇 칸만 옮겨져도 완전히 다른 입력으로 봅니다. 또 이미지가 커지면 첫 층의 가중치 수가 폭발합니다(224×224×3 컬러 이미지면 은닉 노드 128개에 약 1,930만 개). 4장의 CNN은 가로·세로 구조를 유지한 채 작은 필터를 이미지 전체에 공유해 이 두 문제를 함께 해결합니다.

## 코드로 확인하기

코드 박스: theory/code/ch03_mlp.py 핵심 발췌 · 실행 통과(Python 3.13, NumPy 2.5)

```python
import math
import numpy as np

rng = np.random.default_rng(0)

# 1) 파라미터 수와 2) 배치·반복 수
total = sum(n_in * n_out + n_out for n_in, n_out in [(784, 128), (128, 10)])
iters = math.ceil(55_000 / 64)
print(f"파라미터 {total:,}  에폭당 반복 {iters}  마지막 배치 {55_000 - (iters - 1) * 64}")

# 3) 순전파 Shape: [N,1,28,28] → [N,10]
images = rng.random((4, 1, 28, 28))
W1, b1 = rng.normal(0, 0.05, (784, 128)), np.zeros(128)
W2, b2 = rng.normal(0, 0.05, (128, 10)), np.zeros(10)
h0 = images.reshape(4, -1)                # Flatten: 배치 차원은 유지
h1 = np.maximum(0, h0 @ W1 + b1)          # Linear + ReLU
logits = h1 @ W2 + b2
print("Flatten", h0.shape, "→ 은닉층", h1.shape, "→ Logits", logits.shape)

# 4) Dropout: 학습 때 20%를 끄고 남은 값은 1.25배
many = (rng.random((100_000, 10)) >= 0.2) / 0.8
print("학습 모드 평균 ≈", round(float(many.mean()), 3))

# 6) 활성화 함수 없이 Linear 두 개 = Linear 하나
x1 = rng.normal(size=(5, 1))
L1_W, L1_b = rng.normal(size=(1, 8)), rng.normal(size=8)
L2_W, L2_b = rng.normal(size=(8, 1)), rng.normal(size=1)
stacked = (x1 @ L1_W + L1_b) @ L2_W + L2_b
single = x1 @ (L1_W @ L2_W) + (L1_b @ L2_W + L2_b)
print(f"두 층과 한 층의 최대 차이 = {np.abs(stacked - single).max():.1e}")
```

실행 결과: 이번 정리에서 직접 실행

```text
파라미터 101,770  에폭당 반복 860  마지막 배치 24
Flatten (4, 784) → 은닉층 (4, 128) → Logits (4, 10)
학습 모드 평균 ≈ 1.0
두 층과 한 층의 최대 차이 = 8.9e-16
```

⟪box:코드 풀이⟫

- `images.reshape(4, -1)` — `nn.Flatten()`과 같은 일입니다. `-1`은 "나머지를 알아서 계산"이라는 뜻이라 `1×28×28=784`가 됩니다.
- `np.maximum(0, ...)` — ReLU입니다. 음수만 0으로 바꿉니다.
- `(rng.random(...) >= 0.2) / 0.8` — 80% 확률로 남는 마스크를 만들고 0.8로 나눠 1.25배합니다. 평균이 1.0으로 유지되는 것이 Inverted Dropout의 핵심입니다.
- 역전파 검증 — 파일 전체를 실행하면 5번에서 연쇄법칙으로 구한 기울기(0.387571)와 가중치를 아주 조금 움직여 직접 잰 기울기(0.387571)가 같게 나옵니다. `loss.backward()`가 하는 계산이 이것입니다.
- `stacked`와 `single` — 차이 `8.9e-16`은 컴퓨터의 반올림 오차 수준으로 사실상 0입니다. 두 선형 층은 한 층으로 합쳐집니다. ReLU를 넣으면 차이가 커져 더는 한 층으로 줄일 수 없습니다.

⟪/box⟫

## PyTorch로 옮기기

코드 박스: PyTorch 예시 · Python · 미검증(이 환경에 PyTorch 미설치)

```python
import torch
import torch.nn as nn
from torch.utils.data import DataLoader, random_split
from torchvision import datasets, transforms

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
full = datasets.MNIST("data", train=True, download=True, transform=transforms.ToTensor())
train_set, val_set = random_split(full, [55_000, 5_000])
train_loader = DataLoader(train_set, batch_size=64, shuffle=True)
val_loader = DataLoader(val_set, batch_size=64, shuffle=False)

model = nn.Sequential(
    nn.Flatten(),
    nn.Linear(28 * 28, 128),
    nn.ReLU(),
    nn.Dropout(0.2),
    nn.Linear(128, 10),                   # 로짓으로 끝낸다
).to(device)
loss_function = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)


def evaluate(loader):
    model.eval()                          # Dropout 끄기
    total_loss, correct, count = 0.0, 0, 0
    with torch.no_grad():                 # 기울기 계산 멈춤
        for images, labels in loader:
            images, labels = images.to(device), labels.to(device)
            logits = model(images)
            total_loss += loss_function(logits, labels).item() * len(labels)
            correct += (logits.argmax(dim=1) == labels).sum().item()
            count += len(labels)
    return total_loss / count, correct / count


for epoch in range(5):
    model.train()                         # Dropout 켜기
    for images, labels in train_loader:
        images, labels = images.to(device), labels.to(device)
        optimizer.zero_grad()
        loss = loss_function(model(images), labels)
        loss.backward()
        optimizer.step()
    print(epoch + 1, evaluate(val_loader))
```

⟪box:코드 풀이⟫

- `random_split(full, [55_000, 5_000])` — 학습 데이터에서 검증 데이터를 떼어 냅니다. 테스트 데이터(`train=False`)는 이 단계에서 건드리지 않습니다.
- `nn.Sequential(...)` — 슬라이드 15의 구조 그대로이며, 마지막에 Softmax가 없습니다.
- `.to(device)` — 모델과 배치를 같은 장치에 둡니다. 둘이 다르면 실행 오류가 납니다.
- `loss.item() * len(labels)` — 배치마다 크기가 다를 수 있으므로(마지막 배치 24장) 샘플 수로 가중해 누적한 뒤 전체 개수로 나눕니다. 배치 평균을 그냥 평균하면 마지막 배치가 과대 반영됩니다.
- `model.train()` / `model.eval()` — 에폭마다 학습·평가 모드를 바꿉니다.

⟪/box⟫

## 강의 자료 바로잡기

| 위치 | 원본 표기 | 바로잡은 내용 | 근거 |
|---|---|---|---|
| 슬라이드 4 | `nn.Linear(1, 8), nn.Linear(8, 1), nn.Sigmoid()` | 두 `Linear` 사이에 `nn.ReLU()`가 필요합니다. 없으면 로지스틱 회귀와 같은 선형 모델입니다 | 코드 6번 결과 |
| 슬라이드 5 | 모델 안에 Softmax 층 | 개념도로는 맞지만 PyTorch 구현은 로짓으로 끝내고 `CrossEntropyLoss`가 Softmax를 포함합니다(슬라이드 6·16과 일치시킴) | PyTorch 공식 문서 |
| 슬라이드 9 | Train 85% / Validation 15% | 개념 예시 비율. 실습은 55,000 / 5,000(약 91.7% / 8.3%) | 실습 노트북 |
| 슬라이드 12·13 | DataLoder | DataLoader | 철자 |
| 슬라이드 14 | 1 Epoch = 860 Iterations | 맞음. 단 마지막 배치는 24장이며 `drop_last=True`면 859 | `$55{,}000=64\times859+24$` |
| 슬라이드 22 | `display_logits = model(images)` 다음 줄에서 `logits` 사용 | 변수 이름을 하나로 통일: `logits = model(images)` | 그대로 실행하면 `NameError` |

## 스스로 점검

1. 입력 784, 은닉 256, 출력 10인 MLP의 파라미터 수는? → `$784\times256+256+256\times10+10=203{,}530$`개입니다.
2. 학습 데이터 50,000장, 배치 128이면 에폭당 반복 수는? → `$\lceil50{,}000/128\rceil=391$`번입니다.
3. 평가할 때 `model.eval()`을 빼먹으면? → Dropout이 켜진 채 예측해 결과가 흔들리고 정확도가 낮게 나옵니다.
4. Validation Loss가 3 에폭부터 오르기 시작했습니다. 어떻게 하나요? → 과적합 신호입니다. 가장 낮았던 에폭의 모델을 저장해 쓰거나, Dropout·데이터 증강으로 규제를 늘립니다.
